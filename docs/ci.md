# Website CI

The `ci` workflow runs on pull requests and pushes to `main`. Both jobs check out the exact PR head (or pushed commit), use read-only repository contents permission, and disable persisted checkout credentials. There are no inherited secrets, privileged pull-request triggers, deployments, or new services.

- `ci / build-test`: Node 22, `npm ci`, the site build, byte equality for every page generated by `build:site`, and the existing `npm test`. The worker-support generator exercised by `npm test` is separate from the site-page equality check.
- `ci / security`: Gitleaks working-tree scan with full redaction, Semgrep public `p/ci` rules at ERROR severity with failing exit codes and strict error handling, and a blocking high-severity npm dependency audit. No exclusions or finding baselines are added. Semgrep prints only rule IDs, paths, line numbers and error types; raw scanner reports are temporary runner files, never published artifacts.

## Public tool provenance

This adapter is independently authored from public tool interfaces. It does not copy private workflow implementation or configuration.

- [Checkout v4.2.2](https://github.com/actions/checkout/tree/v4.2.2): `11bd71901bbe5b1630ceea73d27597364c9af683`.
- [Setup Node v4.1.0](https://github.com/actions/setup-node/tree/v4.1.0): `39370e3970a6d050c480ffad4ff0ed4d3fdee5af`.
- [Setup Python v5.6.0](https://github.com/actions/setup-python/tree/v5.6.0): `a26af69be951a213d495a4c3e4e4022e16d87065`.
- [Gitleaks 8.30.1](https://github.com/gitleaks/gitleaks/releases/tag/v8.30.1), CLI `dir` and `--redact=100`. The Linux x64 archive SHA-256 is checked against `551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb`, from the release's published checksums. Built-in rules come from this pinned binary.
- [Semgrep 1.187.0](https://pypi.org/project/semgrep/1.187.0/) and [CLI reference](https://semgrep.dev/docs/cli-reference). The public [p/ci registry policy](https://semgrep.dev/p/ci) is fetched each run; policy rules may evolve independently of the pinned CLI. No private rules or account token is used.

`js-yaml` is locked to 3.15.2 within `front-matter`'s existing `^3.13.1` range to resolve the reported high-severity dependency findings. No direct dependency range or product copy changes accompany the CI adapter.
